# ความแตกต่างจาก QB64 และ QBasic

[สารบัญคู่มือ](../README.md) · [English](../en/differences.md)

QBNex เริ่มต้นจาก QB64 โปรแกรมเดิมควรคอมไพล์ได้และให้ผลลัพธ์เหมือนเดิม
หน้านี้รวบรวมจุดที่ไม่เหมือนพร้อมเหตุผล รายละเอียดและเทสต์ของแต่ละข้ออยู่ใน
[`docs/dev/deviations.md`](../../dev/deviations.md)

## ตัวเครื่องมือ

- **ไม่มี IDE** QBNex เป็นคอมไพเลอร์แบบ command line (`qb`, `qbnex`)
  ใช้ editor อะไรก็ได้ และ VS Code มี[ส่วนขยาย](vscode.md) ไม่รองรับ
  `$DEBUG` และ switch `-l` ของ IDE ใน QB64
- **ไลบรารีมาตรฐานและ `'$IMPORT`** เป็นส่วนที่ QBNex เพิ่มเข้ามา
  ([ไลบรารีมาตรฐาน](stdlib.md)) โมดูลที่ import จะถูกยกตำแหน่ง: ส่วนประกาศ
  ไปไว้ก่อนโปรแกรม และ procedure ไปไว้หลังโปรแกรม
- **encoding ของ source:** ไฟล์ CP437 คอมไพล์ได้โดยไบต์ไม่เปลี่ยน
  ไฟล์ UTF-8 ก็ได้
- **runtime เป็น Rust** ไม่ลิงก์ OpenGL, FreeGLUT, FreeType, miniaudio หรือ
  zlib พฤติกรรมถูกตรวจเทียบกับ runtime เดิมด้วยเทสต์แบบ differential
  (เปรียบเทียบผลลัพธ์หลายพันล้านค่า ไม่ตรงกัน 0 ค่า นอกเหนือจากรายการด้านล่าง)

## สิ่งที่ตั้งใจเปลี่ยน (แก้บั๊ก)

- `VAL("123E-2")` ได้ `1.23` (QB64 ได้ `.000123` เพราะใส่เครื่องหมายของเลขยกกำลังหลัง normalise)
- การปัดเป็นจำนวนเต็ม (`CINT`, `CLNG`, การกำหนดค่าให้ตัวแปรจำนวนเต็ม) ปัดแบบ half-even บนทุก CPU (QB64 บน ARM ปัดครึ่งหนีจากศูนย์)
- `VAL` อ่านเลขนัยสำคัญได้ตรงถึง 1000 หลัก (QB64 เขียนเกิน buffer เมื่อยาวกว่า 256)
- `STR$` ของ double ที่ต้องใช้ทศนิยมเกิน 19 หลักพิมพ์ตัวเลขออกมาจริง (QB64 พิมพ์ ` .0f`) และ `STR$` ของ SINGLE ที่ไม่ใช่ค่าจำกัดได้ ` 0`
- ค่า DOUBLE และ `_FLOAT` พิมพ์แบบเดียวกับ QBasic 4.5 และ QB64 (`PRINT`, `STR$`, `PRINT #`, `WRITE`) คือเลขนัยสำคัญไม่เกิน 16 หลักและไม่มีศูนย์ต่อท้าย `PRINT 2.5#` แสดง ` 2.5`
- โค้ดของ main module ที่อยู่ก่อน SUB แรกยังอยู่ใน main module และ handler ของ `ON ERROR GOTO` ใน main module ใช้ได้
- `_MEMFREE` ของ block จาก `_MEMNEW` ไม่คืนหน่วยความจำซ้ำสองครั้งอีกแล้ว (QB64 ทำ heap เสียหาย)
- จุดที่ QB64 อ่านเกิน buffer (GET ของ string, FILES, SHELL, `_PUTIMAGE` แบบยืด, GET แบบ 2-bit, HEX$) ตอนนี้ได้ผลที่กำหนดแน่นอน
- `SHELL` หยุดรับ event ของหน้าต่างตลอดช่วงที่รอคำสั่ง
- นาฬิกามิลลิวินาทีเป็น 64-bit ทุกระบบ (QB64 บน Windows วนกลับเมื่อครบ 24.8 วัน)
- `_CLIPBOARD$` และ `_CLIPBOARDIMAGE` ใช้บน Linux และ macOS ได้ด้วย (clipboard เป็น UTF-8 ไบต์ที่ไม่ใช่ UTF-8 จะกลายเป็น U+FFFD)
- `_OPENCLIENT` ลองทุกที่อยู่ IPv4 ของ host บนทุกระบบ
- ไฟล์ source แบบ CP437 คอมไพล์ได้
- แก้คอมไพเลอร์: wrapper ของ `CALL ABSOLUTE`, `PLAY ON/OFF/STOP` และ `ON PLAY(n) GOSUB` คอมไพล์ได้และ event ของ PLAY ทำงาน, ตัวดำเนินการเปรียบเทียบใน PRINT
- `PLAY "Nn"` เล่นโน้ตตาม QBasic (N0 คือช่วงเงียบ), `PLAY(n)` นับเป็นจำนวนโน้ต, `SOUND f, 0` หยุดเสียงที่เล่นอยู่, `PLAY "X" + VARPTR$(s$)` ใช้ได้ และ `_SNDOPEN` ที่ใส่ "VOL" หรือ "SYNC" ยังใช้ `_MEMSOUND` ได้
- `SOUND`, `BEEP` และ `PLAY` มีเสียงและ `PLAY(n)` นับถอยลง (synth ของ QB64 ไม่มีเสียง) ในโหมด `MF` (ค่าเริ่มต้น) คำสั่งจะรอจนโน้ตของมันเล่นจบ เหมือน QBasic (QB64 ไม่เคยรอ)
- `\` และ `MOD` ของจำนวนเต็มเมื่อหารด้วยศูนย์เป็น error 11 ธรรมดาที่ `ON ERROR` และ `TRY`/`CATCH` ดักได้ (เหมือน QBasic 4.5) ขณะที่ QB64 จบโปรแกรม
- READ ตัวเลขทศนิยมเข้า DOUBLE/`_FLOAT` ปัดค่าได้ถูกต้อง
- เมื่อ output ถูก redirect หรือตั้ง `QBNEX_NO_ERROR_DIALOG=1` runtime error จะพิมพ์หนึ่งบรรทัดทาง stderr แล้วออกด้วย exit code 1 แทนการเปิดกล่องข้อความ
- `PUT` ไปยังการเชื่อมต่อ TCP ที่ send buffer เต็มจะไม่ทำให้การเชื่อมต่อหลุดอีก ข้อมูลที่เหลือจะถูกเก็บไว้แล้วส่งต่อตามลำดับเมื่อเรียกคำสั่งเครือข่ายครั้งถัดไปหรือ `CLOSE` (QB64 ตัดการเชื่อมต่อและข้อมูลหาย)

## พฤติกรรมของ QBasic ที่ตั้งใจคงไว้

ส่วนนี้เหมือน QB64 (ผลลัพธ์อ้างอิงของเทสต์พึ่งพามันอยู่): `MKSMBF$(0)` ได้
exponent ของ MBF เป็น 2, `STR$`
ของ infinity/NaN ได้ ` 0`, กราฟิกยังแปลงทศนิยมเป็นจำนวนเต็มแบบ QB64,
`_CONNECTIONADDRESS` แสดง port ปลายทางแบบไบต์สลับกัน, TIMER รอให้ถึงวินาที
ถัดไปตอนโปรแกรมเริ่ม

## ข้อบกพร่องที่รู้แล้ว

ตอนนี้ไม่มีข้อบกพร่องที่ค้างอยู่ ดูที่[ข้อจำกัดและความต่างจาก QB64](limitations.md#ข้อบกพร่องที่ยังไม่ได้แก้)

## ช่องว่างตามแพลตฟอร์ม

`_SCREENIMAGE`, `_SCREENCLICK` และ `_SCREENPRINT` คอมไพล์ได้ แต่
`_SCREENIMAGE` ได้ภาพว่างบน Linux/macOS, `_SCREENCLICK` และ
`_SCREENPRINT` ไม่ทำอะไรบน Linux, การพิมพ์ (`LPRINT`, `_PRINTIMAGE`)
ส่งไปเครื่องพิมพ์หลักบน Windows และผ่าน `lp` บน Linux และ macOS

- Linux: OPEN … LOCK READ และ LOCK WRITE ปฏิเสธการ OPEN ไฟล์นั้นทุกครั้งจากที่อื่น
  ไม่ใช่แค่การเข้าถึงที่ขัดกัน (เข้มงวดกว่า Windows) การล็อกเป็นแบบ advisory:
  เห็นได้เฉพาะโปรแกรมที่ล็อกไฟล์ (โปรแกรม QBNex, ผู้ใช้ `flock`/`fcntl`)
  OPEN ที่ไม่มีส่วน LOCK จะได้ล็อกแบบใช้ร่วม (shared lock)
- macOS: ไม่บังคับใช้ส่วน LOCK ของ OPEN และช่วงที่ LOCK เป็นของทั้งโปรเซส
  การปิดหมายเลขไฟล์อื่นของไฟล์เดียวกันจะปลดล็อกด้วย

## คอมไพเลอร์และ runtime

- โปรแกรมถูกคอมไพล์เป็น QIR แล้วรันด้วย runner ภาษา Rust
  (ดู[คำสั่ง](commands.md#โปรแกรมถูก-build-อย่างไร))
  `-x` และ `-z` ไม่เปลี่ยนอะไร (แสดงผลทาง console เสมอ) ส่วน `-p`,
  `-s:debuginfo` และ `--ir` รับได้แต่ไม่มีผล ฟังก์ชันใน `DECLARE LIBRARY`
  ถูกเรียกใน shared library ผ่าน `crates/engine/ffi` (ดู[ส่วนขยายของภาษา](language.md))
  ส่วนตำแหน่งที่ค้นหาไลบรารีดูที่[ข้อจำกัด](limitations.md#declare-library)
- ถ้าใช้คำสั่งที่ QIR back end ยังไม่รองรับ การ build จะหยุดพร้อมข้อความ
  `QIR: unsupported: line N: ...`
- path แบบ relative ใน `$INCLUDE` ค้นข้างไฟล์ที่ include ก่อน แล้วข้างไฟล์ source หลัก แล้วในโฟลเดอร์
  ที่เรียก `qb` และ `'$INCLUDEONCE` (QB64-PE) ในไฟล์ทำให้ไฟล์นั้นถูก include ครั้งเดียว
- บน Linux/macOS ถ้าไม่พบไฟล์ตามชื่อที่เขียนพอดี ชื่อใน `$INCLUDE` จะถูกค้นแบบไม่สนตัวพิมพ์เล็ก/ใหญ่
  ทีละโฟลเดอร์ (ชื่อที่ตรงพอดีมาก่อน) และ `$IF` ไม่ยุ่งกับโครงสร้างบล็อกของโค้ด
  (QB64 ปิดบล็อกที่เปิดอยู่เมื่อเจอ `$END IF`)
- INPUT ที่ stdin ถูกเปลี่ยนทาง: คำตอบที่ไม่ตรงกับตัวแปรจะแสดง "Redo from start" แล้วอ่านบรรทัดถัดไป
  เมื่อไม่มีข้อมูลเหลือ จะใช้คำตอบตามที่ได้รับ (ค่าที่ขาดเป็น 0 / "") แทนการรอไม่สิ้นสุด
- `_SNDLIMIT` นับเวลาจากตอนที่เสียงเริ่มเล่น (QB64 ใช้เวลาสัมบูรณ์ของเอนจินเสียง)
- `TIME$ =` และ `DATE$ =` เลื่อนนาฬิกาของโปรแกรม (TIME$, DATE$, TIMER) ไม่ใช่นาฬิกา
  ของระบบ ส่วน QB64 ไม่ทำอะไร `_MEM` ของ STRING ความยาวไม่คงที่ และ `_MEMFILL`
  ของค่าที่ไม่ใช่ตัวแปรโดยไม่มี `AS` ใช้ได้ (ดู[ข้อจำกัด](limitations.md))
- `_MAPTRIANGLE` แบบ 3 มิติไม่มีระนาบไกล (ดู[กราฟิก](graphics-3d.md))
- ข้อจำกัดของรุ่นเว็บ: ดู[รันบนเว็บ](web.md)
