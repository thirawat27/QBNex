# ความแตกต่างจาก QB64 และ QBasic

[สารบัญคู่มือ](../README.md) · [English](../en/differences.md)

QBNex เริ่มต้นจาก QB64 โปรแกรมเดิมควรคอมไพล์ได้และให้ผลลัพธ์เหมือนเดิม
หน้านี้รวบรวมจุดที่ไม่เหมือนพร้อมเหตุผล รหัส (D-xx, L-xx) ตรงกับใน
[`docs/dev/deviations.md`](../../dev/deviations.md) ซึ่งมีรายละเอียดและเทสต์ประกอบ

## ตัวเครื่องมือ

- **ไม่มี IDE** QBNex เป็นคอมไพเลอร์แบบ command line (`qb`, `qbnex`)
  ใช้ editor อะไรก็ได้ และ VS Code มี[ส่วนขยาย](vscode.md) ไม่รองรับ
  `$DEBUG` และ switch `-l` ของ IDE ใน QB64
- **ไลบรารีมาตรฐานและ `'$IMPORT`** เป็นส่วนที่ QBNex เพิ่มเข้ามา
  ([ไลบรารีมาตรฐาน](stdlib.md)) โมดูลที่ import จะถูกยกตำแหน่ง: ส่วนประกาศ
  ไปไว้ก่อนโปรแกรม และ procedure ไปไว้หลังโปรแกรม (D-25)
- **encoding ของ source:** ไฟล์ CP437 คอมไพล์ได้โดยไบต์ไม่เปลี่ยน
  ไฟล์ UTF-8 ก็ได้ (D-22)
- **runtime เป็น Rust** ไม่ลิงก์ OpenGL, FreeGLUT, FreeType, miniaudio หรือ
  zlib พฤติกรรมถูกตรวจเทียบกับ runtime เดิมด้วยเทสต์แบบ differential
  (เปรียบเทียบผลลัพธ์หลายพันล้านค่า ไม่ตรงกัน 0 ค่า นอกเหนือจากรายการด้านล่าง)

## สิ่งที่ตั้งใจเปลี่ยน (แก้บั๊ก)

| รหัส | สิ่งที่เปลี่ยน |
| --- | --- |
| D-01 | `VAL("123E-2")` ได้ `1.23` (QB64 ได้ `.000123` เพราะใส่เครื่องหมายของเลขยกกำลังหลัง normalise) |
| D-02 | การปัดเป็นจำนวนเต็ม (`CINT`, `CLNG`, การกำหนดค่าให้ตัวแปรจำนวนเต็ม) ปัดแบบ half-even บนทุก CPU (QB64 บน ARM ปัดครึ่งหนีจากศูนย์) |
| D-03 | `VAL` อ่านเลขนัยสำคัญได้ตรงถึง 1000 หลัก (QB64 เขียนเกิน buffer เมื่อยาวกว่า 256) |
| D-04, D-05 | `STR$` ของ double ที่ต้องใช้ทศนิยมเกิน 19 หลักพิมพ์ตัวเลขออกมาจริง (QB64 พิมพ์ ` .0f`) และ `STR$` ของ SINGLE ที่ไม่ใช่ค่าจำกัดได้ ` 0` |
| D-06 | โค้ดของ main module ที่อยู่ก่อน SUB แรกยังอยู่ใน main module และ handler ของ `ON ERROR GOTO` ใน main module ใช้ได้ |
| D-07 | `_MEMFREE` ของ block จาก `_MEMNEW` ไม่คืนหน่วยความจำซ้ำสองครั้งอีกแล้ว (QB64 ทำ heap เสียหาย) |
| D-08, D-10, D-11, D-12, D-R12b-1, D-R12b-3 | จุดที่ QB64 อ่านเกิน buffer (GET ของ string, FILES, SHELL, `_PUTIMAGE` แบบยืด, GET แบบ 2-bit, HEX$) ตอนนี้ได้ผลที่กำหนดแน่นอน |
| D-09 | `SHELL` หยุดรับ event ของหน้าต่างตลอดช่วงที่รอคำสั่ง |
| D-18 | นาฬิกามิลลิวินาทีเป็น 64-bit ทุกระบบ (QB64 บน Windows วนกลับเมื่อครบ 24.8 วัน) |
| D-19, D-20 | `_CLIPBOARD$` และ `_CLIPBOARDIMAGE` ใช้ได้บน Linux/macOS (clipboard เป็น UTF-8 ไบต์ที่ไม่ใช่ UTF-8 จะกลายเป็น U+FFFD) |
| D-21 | `_OPENCLIENT` ลองทุกที่อยู่ IPv4 ของ host บนทุกระบบ |
| D-22 | ไฟล์ source แบบ CP437 คอมไพล์ได้ (QBNex รุ่นก่อนไม่รับ) |
| D-23, D-24, D-26 | แก้คอมไพเลอร์: wrapper ของ `CALL ABSOLUTE`, `PLAY ON/OFF/STOP` และ `ON PLAY(n) GOSUB` คอมไพล์ได้ (แต่ตัว event ของ PLAY ยังไม่ถูกยิง), ตัวดำเนินการเปรียบเทียบใน PRINT |
| D-R12b-5 | `\` และ `MOD` ของจำนวนเต็มเมื่อหารด้วยศูนย์เป็น error 11 ธรรมดาที่ `ON ERROR` และ `TRY`/`CATCH` ดักได้ (เหมือน QBasic 4.5) ขณะที่ QB64 จบโปรแกรม |
| D-R12b-2 | READ ตัวเลขทศนิยมเข้า DOUBLE/`_FLOAT` ปัดค่าได้ถูกต้อง |
| D-R12b-4 | เมื่อ output ถูก redirect หรือตั้ง `QBNEX_NO_ERROR_DIALOG=1` runtime error จะพิมพ์หนึ่งบรรทัดทาง stderr แล้วออกด้วย exit code 1 แทนการเปิดกล่องข้อความ |
| D-R11b-1 | `PUT` ไปยังการเชื่อมต่อ TCP ที่ send buffer เต็มจะไม่ทำให้การเชื่อมต่อหลุดอีก ข้อมูลที่เหลือจะถูกเก็บไว้แล้วส่งต่อตามลำดับเมื่อเรียกคำสั่งเครือข่ายครั้งถัดไปหรือ `CLOSE` (QB64 ตัดการเชื่อมต่อและข้อมูลหาย) |

## พฤติกรรมของ QBasic ที่ตั้งใจคงไว้

ส่วนนี้เหมือน QB64 (ผลลัพธ์อ้างอิงของเทสต์พึ่งพามันอยู่): `MKSMBF$(0)` ได้
exponent ของ MBF เป็น 2, DOUBLE บางค่าพิมพ์ศูนย์ต่อท้าย (`-2.50`), `STR$`
ของ infinity/NaN ได้ ` 0`, กราฟิกยังแปลงทศนิยมเป็นจำนวนเต็มแบบ QB64,
`_CONNECTIONADDRESS` แสดง port ปลายทางแบบไบต์สลับกัน, TIMER รอให้ถึงวินาที
ถัดไปตอนโปรแกรมเริ่ม

## ข้อบกพร่องที่รู้แล้วแต่ยังไม่แก้

ดูที่[ข้อจำกัดและความต่างจาก QB64](limitations.md#ข้อบกพร่องที่ยังไม่ได้แก้)

## ช่องว่างตามแพลตฟอร์ม

`_SCREENIMAGE` ได้ภาพว่างบน Linux/macOS, `_SCREENCLICK` และ
`_SCREENPRINT` ไม่ทำอะไรบน Linux, การพิมพ์ (`LPRINT`, `_PRINTIMAGE`)
ใช้ได้เฉพาะ Windows

## หลัง cutover ไปใช้ QIR

- โปรแกรมถูกคอมไพล์เป็น QIR แล้วรันด้วย runner ภาษา Rust (ดู[คำสั่ง](commands.md))
  ไม่มีการสร้างโค้ด C++ อีก ดังนั้น `-z`, `-p`, `-s:debuginfo` และ `--ir`
  จึงไม่มีผล ฟังก์ชันใน `DECLARE LIBRARY` ถูกเรียกใน shared library ผ่าน
  `crates/engine/ffi` (ดู[ส่วนขยายของภาษา](language.md))
- ถ้าใช้คำสั่งที่ QIR back end ยังไม่รองรับ การ build จะหยุดพร้อมข้อความ
  `QIR: unsupported: line N: ...`
- พารามิเตอร์ BYREF ถูกคัดลอกเข้าและคัดลอกกลับ ต่างจาก QB64 เฉพาะเมื่อ SUB
  แก้ตัวแปรตัวเดียวกันทั้งผ่านพารามิเตอร์และผ่าน SHARED
- 3 มิติบน GPU ตัดภาพที่ระนาบไกล (เหมือน OpenGL ของ QB64) แต่ตัววาดแบบ
  ซอฟต์แวร์ไม่ตัด
- ข้อจำกัดของรุ่นเว็บ: ดู[รันบนเว็บ](web.md)
