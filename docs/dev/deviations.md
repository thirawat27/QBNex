# Legacy defects and intentional deviations

Reference for the conformance cases marked `.xfail` or `.deviation`.
A legacy defect is a bug of the legacy QB64-based implementation found by the test corpus; an
intentional deviation is a place where QBNex differs from that implementation on purpose. User-facing summaries are in
[Differences from QB64 and QBasic](../manual/en/differences.md) and [Limitations](../manual/en/limitations.md).

## Legacy defects

Kept defects are conformance `xfail` cases; the runner reports `XPASS` once one is fixed.

## Output quirks preserved bug-for-bug

Golden files depend on these.

- `MKSMBF$(0)` yields MBF exponent 2 (`00 00 00 02`), not zero.
- `MKDMBF$(-0#)` and tiny/huge doubles raise overflow (error 5).
- `STR$` of infinity or NaN is ` 0`.
- Graphics code keeps legacy float handling: `qbr_float_to_long` on SINGLE coordinates, `cvttsd2si` saturation to `INT_MIN`, and C wrap-around in CIRCLE/LINE arithmetic.
- `_CONNECTIONADDRESS` of an accepted connection shows the remote port with its two bytes swapped on little-endian CPUs (legacy read the network-order field as a native `uint16`).
- `_CONNECTIONADDRESS` of a host asks `api.ipify.org` for the public address (sending `GET api.ipify.org HTTP/1.1`, as legacy did) and waits up to 5 s; it falls back to `127.0.0.1`.
- `_SCREENCLICK` always presses the left button once before the requested button; `_SCREENPRINT` sends SHIFT + key 255 for characters the keyboard layout cannot type.
- TIMER's start-up waits for the wall clock's second to tick over (up to one second at program start).

## Intentional deviations

| Change | Why |
| --- | --- |
| Synth voices are mixed into the output and drain, so `PLAY(n)` counts down. In `MF` mode (the default) `SOUND`/`PLAY` wait until their notes have played, as in QBasic; after `MB` they wait only while more than 10 s per voice is queued. Without an output device a silent device keeps real time; `QB_AUDIO_DEVICE=none` starts no engine, so nothing waits (conformance goldens are unchanged). | Legacy output was silence and never blocked. |
| When a chord (`,`) is followed by a longer note or pause, the grown part of the PLAY buffer is silence; legacy left it uninitialised (`realloc`). The legacy `memset` that zeroes part of the chord is kept. | Defined output instead of heap garbage. |
| Noise waveforms use the MSVCRT/UCRT `rand()` LCG (seed 1) on every platform and no longer share the C runtime's `rand()` state. | Identical noise on all platforms; matches the legacy Windows build exactly. |
| Decoders: symphonia (WAV, FLAC, MP3, Ogg Vorbis) and xmrs (MOD, XM, S3M, IT, rendered once, loops not repeated, max 30 min). **MIDI (tinysoundfont + AWE32 ROM) and RAD v2 are dropped**: `_SNDOPEN` returns -1. "STREAM" sounds are decoded completely at open (still not copyable and not `_MEMSOUND`-able, as legacy). Resampling to the device rate is linear without miniaudio's low-pass filter. WAV keeps its integer sample format for `_MEMSOUND`, other formats are f32, modules s16 stereo. | No pure-Rust MIDI synth with an embedded bank; RAD has no Rust player. |
| `_SNDBAL` with y/z uses inverse-distance gain and x-direction pan instead of miniaudio's spatializer (no doppler, cones or HRTF-like channel gains). Stereo pan uses miniaudio's `ma_pan_mode_pan` law. | Approximation of the 3-D model. |
| Raw streams (`_SNDRAW`, synth voices) are pulled by the device callback under the engine lock instead of being copied block by block into a ping-pong buffer by `snd_mainloop`. A forced partial block plays without padding; `_SNDRAWLEN` counts queued frames only. Legacy `_SNDLIMIT` semantics (absolute engine time) are kept. | Race-free and independent of the main-loop rate. |
| `PLAY "Nn"`: N1 is O0 C and N84 is O6 B, N0 is a rest (legacy played N0 as O0 C and every N one semitone high). `PLAY(n)` is the number of notes in the background queue (legacy: sample frames). `SOUND f, 0` stops what SOUND and PLAY queued. `PLAY "X" + VARPTR$(s$)` plays s$. `_SNDOPEN` with requirements other than "STREAM" ("VOL", "SYNC", ...) decodes the sound into memory, so `_MEMSOUND` works. | QBasic semantics and QB64 programs that pass "VOL,SYNC". |
| "Hardware" images are rendered in software at SCREEN resolution and then scaled with the frame; edge pixels and bilinear filtering can differ from the OpenGL output. `_DISPLAYORDER _GLRENDER` layers are ignored. |  |
| **Closed.** `SUB _GL` / `_gl*` run on a real OpenGL context. Left: `_glGetString` returns an `_OFFSET` (QB64: STRING), `ON KEY`-style calls of SUB _GL from a SUB are not possible (as in QB64). |  |
| Game controller buttons/axes use gilrs' standard layout (fixed indices, 19 buttons, 8 axes, Y axes down-positive); legacy reported raw driver order. |  |
| Attaching more controllers than `device_max` no longer overflows the heap (legacy assigned `realloc` to a local). |  |
| The process is per-monitor DPI aware (winit), so a 640x480 SCREEN is 640x480 physical pixels; legacy was DPI-unaware and got scaled by Windows. A non-ASCII key no longer emits a stray ANSI keyup on release. |  |
| `DECLARE LIBRARY "x"` where QB64 finds `x.h`/`x.hpp` is a compile error in QBNex (message: `qb_ffi::header_error`). | Headers can hold macros and inline C, which QBNex does not compile. |
| Off x86 (or with `soft-transcendentals`), `f2xm1`/`fyl2x`/`fyl2xp1` inside `EXP` and `^` with a fractional exponent are computed in software: up to one ulp from the x87 result for about 3% of inputs. | The x87 results are not correctly rounded and differ between CPU models. |
| `_FLOAT` parameters or results in `DECLARE LIBRARY` are a compile error in the QIR backend. | `long double` has a compiler-specific C ABI (Win64 MinGW passes it by reference, SysV in x87 memory class, AArch64 Linux as binary128). |
| INPUT of `&H`/`&O`/`&B` into an `_INTEGER64` variable compares with the "largest value" left by an earlier `INTEGER`/`LONG` argument of the same INPUT, or with 2^64-1 when there is none. Legacy read an uninitialised local in that case. | Undefined in legacy. |
| `$CONSOLE` CSRLIN/POS/LOCATE/SCREEN() close the `CONOUT$` handle they open and read a zeroed buffer info when there is no console (legacy leaked one handle per call and read an uninitialised structure). `_CONSOLEINPUT` mouse Y subtracts the real window top (legacy: uninitialised). | Resource leak / undefined values. |
| Non-Windows `$CONSOLE` LOCATE with only a column writes `ESC[<col>G` (legacy passed one argument to a two-argument format). Unverified on Linux/macOS. | Undefined in legacy. |
| `VAL` applies the sign to the written exponent. | QBasic semantics; legacy result is wrong by powers of ten. |
| Rounding is QBasic round-half-even on every CPU. Legacy non-x86 builds rounded half away from zero (`f+0.5` truncation). | One behaviour on all platforms, matching x86 and QBasic. |
| `VAL` keeps 1000 significant digits exactly and treats further non-zero digits as "slightly more". Legacy overran a 256-byte buffer past 256 digits (undefined behaviour). | Defined behaviour; correctly rounded up to 1000 digits. |
| `STR$` prints all decimals the legacy algorithm asks for, also beyond 19. | Legacy output was garbage from a malformed printf format. |
| `STR$` of a non-finite SINGLE is ` 0`. Legacy read a stale static buffer (result depended on the previous call). | Defined result, same as DOUBLE. |
| Compiler: the TopLevelRuntime lowering only moves top-level code that follows a SUB/FUNCTION (where it used to be a "between SUB/FUNCTIONs" error) into `SUB QBNEX_TOPLEVEL_RUNTIME0`; code before the first procedure stays in the main module. `SUB`/`FUNCTION` lines inside `DECLARE [DYNAMIC\|CUSTOMTYPE\|STATIC] LIBRARY` are not procedure openings, `END SUB 'comment` closes a procedure, and the runtime SUB is called where main closes instead of at the first `END` (fixes the broken self-host fixpoint and most main-module `ON ERROR` failures). | Legacy moved every main-module line into a SUB called at the end: wrong order, separate locals, broken `ON ERROR`, non-reproducible bootstrap. |
| `_MEMFREE` of a `_MEMNEW` block releases it once. | Legacy corrupted the heap. |
| Undefined legacy reads get defined results: GET of a variable-length string whose header claims more bytes than the record holds copies zero bytes where legacy read past its buffer; FILES pads names whose `.` lies past column 9 without the `memmove`/negative `memset` overrun; `SHELL(...)` returns 1 when the command is a lone leading space (legacy returned an uninitialised value) and 0 when only `command.com` was available. | No legacy behaviour to copy (undefined). |
| `shell_call_in_progress` is set for the whole waited SHELL call instead of only around `WaitForSingleObject`. | The Rust launcher runs as one call; the flag only pauses window events. |
| Stretched `_PUTIMAGE` skips source samples that fall outside the source image. Legacy skipped source clipping when the destination is one pixel wide or high and read past the source buffer. | Defined behaviour instead of reading foreign memory; results inside the source are unchanged. |
| Graphics `GET` in 2-bit modes (SCREEN 1) checks the array size it really writes (ceil(w/4) bytes per row, legacy checked ceil(w/8) and overran the array) and stores the last partial byte of a row left-aligned (legacy stored a stale static byte, so `PUT` drew wrong pixels). | Memory safety and QBasic array layout; `graphics/get_2bit_partial` (`.deviation`). |
| SCREEN 0 layout compares the font in the 40x25/80x25 granularity test (legacy `(f=(16+1))` / `(f=16)` assigned it). | Code defect; every WIDTH path already passes fonts 17/16, so no reachable output changes. |
| The millisecond clock (`GetTicks`) is 64-bit everywhere. Legacy Windows used `clock()`, a 32-bit count that overflows after 24.8 days of uptime of the program. | No conformance case (needs 25 days); `systime.rs` unit tests. |
| `_CLIPBOARD$` on Linux/macOS goes through `arboard`: the system clipboard is UTF-8, so bytes that are not valid UTF-8 are stored as U+FFFD; without a display a clipboard private to the process is used (legacy: empty, or a GUI-only X11 owner). Windows keeps `CF_TEXT` bytes exactly. | No conformance case (needs a desktop clipboard). |
| `_CLIPBOARDIMAGE` (read and write) works on Linux/macOS through `arboard`; legacy did nothing there. | Closes a platform gap; no conformance case (desktop). |
| Compiler: source that is not UTF-8 is read as 8-bit (CP437) bytes, kept exactly as written, like QBasic and QB64. The encoding error stays for NUL bytes (UTF-16 without BOM) and for invalid bytes in a file that is otherwise UTF-8 (UTF-8 BOM, or two or more 3-/4-byte UTF-8 sequences). QuickBASIC binary (fast load, `FC 00`) files get their own diagnostic. | QBasic semantics; real programs are CP437. |
| Compiler: the conventional-memory argument check reads the variable id with `VAL(e$)`; a successful include open clears `qberrorhappened`; an internal compiler error prints the error number and compiler line. | Code defect; the old message hid the real error. |
| Compiler: `PLAY {ON\|OFF\|STOP}` and `ON PLAY(n) GOSUB label` are compiled to QIR (`onplay`, `rt PLAYEVENT`); the runner counts the notes in the music queue and runs the handler as a module-level GOSUB when it drops from n notes to fewer. | QBasic semantics. Without an output device the silent device drains the queue in real time; with `QB_AUDIO_DEVICE=none` no notes are queued, so the handler never runs. |
| Compiler: `'$IMPORT` lines of the main source are resolved before the passes. Each module (with its relative `$INCLUDE` files inlined and its own imports first) is split into its declaration head (before its first SUB/FUNCTION) and its procedure body; all heads are included before the program's first line and all bodies after its last line, and the in-place `$IMPORT` lines are no-ops. Imports inside `$INCLUDE` files keep the old in-place behaviour. The generated `target/qb-temp/imports_head.bas`/`imports_body.bas` hold internal range includes (`'$INCLUDE:'file\|from\|to'`), so diagnostics name the real module file and line. | QBasic modules: module-level declarations belong to the main module wherever the import line is. |
| Compiler: PRINT does not insert an implied `;` next to a relational or logical operator. | Code defect. |
| Compiler: an empty `DIM [SHARED] name()` declares a dynamic array with unknown dimensions (the `COMMON name()` path), sized by the first `REDIM`. | QBasic/QB64 semantics. |
| Compiler: `DIM name AS STRING` may share its name with a built-in function that requires `$` and takes arguments; `name$(` stays the call (a scalar cannot be indexed), the bare name is the variable. Functions without arguments and user SUB/FUNCTION names still conflict. | QBasic accepts it. |
| DOUBLE and `_FLOAT` `STR$`/`PRINT`/`PRINT #`/`WRITE` print at most 16 significant digits without trailing zeros (` 2.5`, ` 42`, `-.25`, ` .3333333333333333`, ` 1D+16`). Legacy used the buffer index of the last significant digit as the digit count, so every value with two or more significant digits got one extra decimal (` 2.50`, ` 42.0`, `-.250`, ` 123456789012345.59`, ` .33333333333333331`). SINGLE is unchanged. Golden cases whose output changed carry a `.deviation` file. | QBasic 4.5 and QB64 print ` 2.5`. |
| `_OPENCLIENT` tries every IPv4 address of the host until one connects; legacy Windows used only the first (`gethostbyname`), legacy Linux/macOS already tried all. | One behaviour on all OSes. |
| `n_roundincrement` (READ / INPUT # into `_INTEGER64` and `_UNSIGNED _INTEGER64`) no longer reads `n_digit[n_exp+1]` with a negative index for numbers below 0.1; such numbers are not rounded up (0.06 reads as 0). Legacy read memory before the array (undefined; usually no rounding). | Defined behaviour; `diff_core` skips these reads (3,089 of 2.26M). |
| READ of a decimal number into `_FLOAT` / DOUBLE uses correctly rounded parsing. MinGW `sscanf("%lf")` was one ulp off for some 17-digit inputs (1 in 2.26M random items, e.g. `6.5535595088869763E245`). | Correct IEEE rounding on every OS. |
| `HEX$` with a minimum width above 16 (never emitted by the compiler) returns at most 16 digits; legacy read before its 16-byte buffer. | Memory safety. |
| An unhandled or critical runtime error does not open the "Unhandled Error #n ... Continue?" dialog when `QBNEX_NO_ERROR_DIALOG` is set (to anything but `0`) or stdout/stderr is redirected (a file, pipe or NUL; a GUI program without console streams keeps its dialogs). It writes one line to stderr (`Unhandled Error #53 - prog.exe: Line: 7 (in main module): File not found`), keeps what was printed before, and ends the program with exit code 1 (critical errors: exit 1 at once). Interactive runs keep the dialog (QB4.5 behaviour). The conformance runner and all smoke scripts set the variable. | Test runs and pipes must never block on, or pop up, a modal dialog. |
| `END` in a console program shows "Press any key to continue" and waits only when stdin and stdout are both the console; with either redirected, or `QBNEX_NO_ERROR_DIALOG=1`, it ends at once. A window program still waits in its window unless the variable is set. The QIR VM never waited at `END`. | Automated runs (docs harness, CI) hung at the prompt. `console/end_noninteractive`. |
| Integer `\` and `MOD` by zero raise error 11 as an ordinary error that `ON ERROR` and `TRY/CATCH` catch (QBasic 4.5); `_ERRORMESSAGE$(11)` is "Division by zero". The target of a failed operation is left unchanged, as in QBasic. The most negative value `\ -1` wraps, as in the VM and JIT. A hardware arithmetic fault in runtime code still ends the program. | Legacy made it a critical error (message box, exit), so programs could not handle it. `errors/div_by_zero_catch` passes. |
| `PUT` on a network handle whose send buffer is full ("would block") keeps the connection (`_CONNECTED` stays -1): the unsent bytes are queued in `qb_runtime::net::Conn` and go out, in order, on the next send, receive, `_CONNECTED` or `CLOSE` (which keeps flushing until a second passes without progress). Fixes the legacy defect where a full send buffer dropped the connection. | `net/send_buffer_full`, unit tests `net::full_send_buffer_*`, `net::close_sends_what_is_still_queued` |
| PCX images whose pixel buffer exceeds 4 GiB fail to load. dr_pcx computed the size in 32 bits and overflowed the heap. | Defined failure instead of memory corruption. |
| JPEG pixels come from `zune-jpeg`, not stb_image: sizes are identical, pixels within a tolerance (mean absolute error < 1, at most 1% of samples off by more than 12; measured worst case 0.36 / 0.70% on chroma-subsampled noise). | JPEG is lossy; IDCT and chroma upsampling are implementation details. |
| PSD, PIC (Softimage) and Radiance HDR are no longer decoded (`_LOADIMAGE` returns -1). A file with their signature still stops the format search, as before. | Rarely used; no small Rust decoder matching stb's conversions. |
| 16-bit PNM (maxval > 255) decodes to the high byte of each sample. stb_image 2.27 converted 8-bit channels and then read them as 16-bit (heap over-read, garbage pixels). | Defined, correct result. |
| BMP palette entries that stb_image never reads (it reads 4 entries fewer than an OS/2 BMP holds; files whose data offset implies a negative palette size) are black. Legacy used uninitialised stack memory. | Defined result. |
| Fonts: size metrics (`_FONTHEIGHT`, baseline), `_FONTWIDTH` of monospace fonts, and the font/handle life cycle match FreeType 2.4.9 exactly. Glyph placement matches for 94-100% of renders, otherwise one pixel off; anti-aliased coverage differs slightly (mean 0.3-8 / 255 per pixel). | `$IF`/`$ELSE`/`$END IF` nesting is kept apart from the block structure: QB64's `$END IF` popped the innermost block whatever it was, so a block opened in a `$IF` branch and closed after `$END IF` (or the reverse) failed to compile. | QBasic behaviour of the selected lines; case `syntax/preif_blocks`. |

| CONST evaluation no longer re-reads evaluated bracket results as text: `1 + NOT 0` is accepted and `17714 AND 17714 OR 0 XOR 0` is 17714 (QB64 gave 2). A typed CONST whose value does not fit its type is "Overflow". | Same result as the expression at run time; case `syntax/const_typed_range`. |
